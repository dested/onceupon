# Lab run 1: how the drawing prompt progressed

- **Date:** 2026-09-22
- **Status:** done (135 agent-mode pictures over three rounds; v5 is the current best)
- **Type:** report
- **Board:** https://board.localhost/t/187

## Setup

45 test phrases (39 single subjects across every category plus 6 two-thing actions), one drawing each per round, drawn by Sonnet 5 from the round's prompt version, rendered by the real engine, named blind by a model that never sees the words, then scored 0-100 by an Opus judge that reads the picture, the ops and the case's expectations and files every fault as a general rule.

Two judging regimes were used, and rounds are only compared within a regime:

| Regime | Rounds | Drawer | Judge | Why |
| --- | --- | --- | --- | --- |
| API | r000 (v1), r001 (v3), r002 (v4, 10/45 judged) | Sonnet 5 via the API, thinking off, streamed | Opus 5.5 via the API | the production path; $6.25 spent, then the account ran out of credits |
| agent | r003 (v3), r004 (v4), r005 (v5) | Sonnet agents in Claude Code with the same prompt and user message | Opus agents in Claude Code reading the jpg | no API money left; same rubric, same data format |

The agent judge scored the same prompt (v3) 5.7 points higher than the API judge (70.9 vs 65.2), so r003 was taken as a fresh baseline instead of comparing across regimes.

## What each patch fixed

**v1 → v3** (API editor, from r000). The seed prompt said "use mirror for every pair". `mirror` reflects across the entity's own axis, so any ear, horn or eye on a side-view head got a twin floating behind the animal (the stray triangle in the horse). v3 restricted mirror to parts centered on the body, added a four-legged template with four explicit legs and per-species signature parts, and gave people identity marks (hair, bow, cane, hat). Horse-family and person categories rose; the floating twin disappeared from every animal.

**v3 → v4** (API editor, from r001). Birds were a tiny wing squiggle with no head; horses had pencil necks and no ears and read as dinosaurs; long-hair ovals hung under chins and read as beards. v4 added an "every animal gets a separate head plus one bold signature part" rule, a real bird recipe, a thick horse neck with ears on top, side-lock hair, verb poses (jumping puts feet above the obstacle, sleeping is low and wide with zzz) and a height-bucketed scale rule for lone subjects. In agent mode: bird 10 → 80, horse 42 → 74, horse eating an apple 60 → 79, cow 66 → 80, cat 68 → 80. Major issues halved (20 → 11). To fit the token cap the editor also deleted star, heart, sun stamp, ball, table and the birthday beat, which the test set cannot see.

**v4 → v5** (Fable, from r003 + r004). The dominant remaining fault kind was too-small (25 of 100 issues in r004): v4 scoped the lone-subject scale rule to "food, toy, animal or vehicle", so a lone pirate, ghost, robot, monster, boy, girl, grandpa, princess, flower or cat-on-a-bed sat small on an empty page. v5 makes the rule cover any single thing, derives scale from the recipe height (300 / height, snapped to 1, 1.5, 2, 3, with the top-of-page check), places flying things at y=330, adds recipes for the three repeat failures without one (frog: head merged into body twice; ghost: tiny faint sheet twice; airplane: hollow box wings then an off-page front view), draws the horse mane as a fringe line (the slab read as a saddle on the unicorn), keeps the pirate hat above the eyes, and restores the deleted short recipes.

Result (r005): 77.5 mean, kept by the rule (+1.8 ≥ 1.5). Every targeted case moved: flower 58 → 79, ghost 68 → 80, frog 69 → 80, airplane 44 → 58, unicorn 63 → 71, rocket 76 → 83, boat 79 → 83, cat on a bed 67 → 71. But the aggregate gain is within the noise of a 45-picture single-sample round: recognizable slipped 4.6 → 4.4, blind-yes 91% → 89%, and major issues rose 11 → 16, mostly wrong-proportion and too-small on cases v5 did not touch (bird in nest 76 → 70, balloon 83 → 80, turtle 89 → 86, owl 87 → 84). Read v4 and v5 as equals on the whole set, with v5 better on its worst cases. A second sample per case (config `samples: 2`) would settle it.

## Harness findings along the way

- The SDK's structured-output helper sends enums and numeric bounds as description text, not JSON Schema constraints, so the API judge occasionally emitted an out-of-enum issue kind; the judge now parses leniently and retries once.
- Vite full-reloads the page on any changed root file outside the module graph (another session's markdown edits, the lab's own data writes), which killed the page-side campaign twice. The dev server now watches only source dirs, and a persisted `running` campaign loads as `paused` for resume.
- The API editor twice produced patches over the 1.3x prompt-token cap; the cap is 1.5x now and the editor is told to trade text out for text in.
- A round is never kept unless at least 90% of its cases were judged (r002 had been "kept" on 10 judged cases before this guard existed).
- The `face` op draws a symmetric front-facing eye pair even on profile heads (judges flagged bug eyes on every side-view animal). That is a renderer trait, not a prompt fault; a profile-aware face would raise every animal score a few points.
